# 仓库文件维护规范

## 文件归属

| 类型 | 是否入库 | 存放位置 |
| --- | --- | --- |
| 源码、测试、依赖清单和 lock 文件 | 是 | 对应模块、`scripts/` |
| Android 工程源码和 Gradle wrapper | 是 | `frontend-app/android/` |
| 应用实际引用的图片、图标、视频 | 是 | 各端 `assets/` 或工程资源目录 |
| 去除真实值的配置示例 | 是 | `config/` 或模块 `.env.example` |
| 项目说明、架构和运维文档 | 是 | 根 `README.md`、`docs/`、模块 README |
| 经核实可共享且用于回归的样本 | 是 | `datasets/`，记录来源和用途 |
| 密钥、真实账号、穿透配置和证书 | 否 | 本地忽略配置 |
| 下载的 FRP 程序、压缩包和安装文件 | 否 | 本地工具目录；不作为项目源码 |
| Python/Node 环境、模型缓存、SDK | 否 | 本地环境或缓存目录 |
| 用户上传、数据库、任务产物、日志 | 否 | `runtime-data/` 等忽略目录 |
| 构建输出、截图、覆盖率及测试报告 | 否 | `dist/`、`.runlogs/`、测试输出目录 |
| 申请材料、协议、草稿及 Office 锁文件 | 否 | 本地资料目录 |
| 来源、使用授权或脱敏情况未确认的语料 | 否 | 本地 `datasets/`，见[样本说明](sample-data.md) |

## 目录和命名

1. 根目录只放跨项目配置、项目说明和工具约定，不堆放下载程序、临时脚本或业务文档。
2. 可共享的运维模板放 `config/<工具>/`；操作说明放 `docs/operations/`。
3. 源码沿用各模块已有命名；脚本用能说明用途的名称。不得以 `temp`、`new`、`final2`、`副本` 充当长期正式命名。
4. 回归和诊断脚本放 `e2e/`、`backend/tests/` 或 `scripts/`，生成结果不与脚本混放。
5. 历史设计文档集中在 `docs/superpowers/specs/`，不为统一外观批量改动已被引用的路径。
6. `.editorconfig` 约定缩进、编码和换行；`.gitattributes` 约定 Git 中的文本换行及二进制类型。不要把整个旧仓库的一次性换行变化混入功能提交。

既有更详细的命名规则见[项目文件命名规范](../superpowers/specs/2026-04-03-project-file-naming-normalization-plan.md)。

## 提交检查

```powershell
git status --short
git diff --check
git diff --stat
git diff --cached --stat
git ls-files -ci --exclude-standard
```

最后一条用于发现“已被忽略、仍在跟踪”的文件。忽略规则不会自动移除已提交文件；应核实后用 `git rm --cached -- <路径>` 停止跟踪，本地文件仍保留。提交时按路径显式暂存，复查差异后再推送。

配置模板只能包含空值或占位符。代码和模板也要检查硬编码密钥；日志、图片、文档和样本不能仅凭扩展名判断是否安全。
