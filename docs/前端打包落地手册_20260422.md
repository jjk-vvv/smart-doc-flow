# 前端打包落地手册（Electron + Capacitor）

## 1. 目标与边界

- 目标：在不改业务功能代码的前提下，完成网页端 `frontend`（Electron）与手机端 `frontend-app`（Capacitor）的可打包落地。
- 边界：本次只调整构建脚本、打包配置、环境参数与打包流程，不触碰模块业务逻辑。

## 2. 产物定义

- 网页端（`frontend`）构建产物：`frontend/dist`，用于 Electron 打包。
- 手机端 Web 访问产物：`frontend-app/dist`（`/m/` 路由基座）。
- 手机端 Native 容器产物：`frontend-app/dist-native`（`/` 路由基座，供 Capacitor `webDir` 使用）。

## 3. 一次性准备

在项目根目录执行：

```powershell
npm --prefix frontend-app install --legacy-peer-deps
```

说明：

- 这一步会安装/锁定 Capacitor 相关依赖，并更新 `frontend-app/package-lock.json`。
- 当前依赖树存在 `lucide-react` 与 `react@19` 的 peer 声明冲突，因此这里固定使用 `--legacy-peer-deps` 以保证安装稳定。
- 若后续执行 Android 打包，需要本机安装 Android Studio、SDK、JDK。
- 若后续执行 iOS 打包，需要 macOS + Xcode（Windows 无法本地出 iOS 包）。

## 4. 日常构建命令

### 4.1 手机端（frontend-app）

```powershell
# Web 子路径部署（/m/）
npm --prefix frontend-app run build:web

# Native 容器部署（/）
npm --prefix frontend-app run build:native
```

### 4.2 根目录编排（推荐）

```powershell
# 手机端 web 构建
npm run build:frontend:app:web

# 手机端 native 构建
npm run build:frontend:app:native
```

## 5. Capacitor 流程

```powershell
# 环境检查
npm run mobile:cap:doctor

# 构建 native 前端并同步到原生工程
npm run mobile:cap:sync

# 打开 Android 工程
npm run mobile:cap:android

# 打开 iOS 工程（需 macOS）
npm run mobile:cap:ios
```

首次接入原生工程时：

```powershell
npm --prefix frontend-app run cap:add:android
npm --prefix frontend-app run cap:add:ios
```

## 6. Electron 流程

```powershell
# 仅目录打包（不生成安装包，包含 Python 运行时）
npm run desktop:pack

# 生成安装包（包含 Python 运行时）
npm run desktop:dist

# 仅打包应用壳（不携带 .venv，目标机器需已有可用 Python 运行时）
npm run desktop:pack:shell
```

打包配置由 `scripts/prepare-desktop-config.cjs` 生成 `electron-builder.generated.json`：

- 默认把仓库 `.venv` 映射到 `app-runtime/.venv`，并排除 `__pycache__`、`pip`、`setuptools`、
  第三方测试目录和调试符号。
- `--skip-python`（或 `SMART_DOC_FLOW_DESKTOP_BUNDLE_PYTHON=0`）生成不携带运行时的壳包，
  启动时回退到系统 `python`（需已安装 `backend/requirements.txt`）。
- 当前 `.venv` 约 2.5 GB、7.7 万文件，打包需要预留至少 6 GB 磁盘和足够内存；
  Electron 首次打包还会下载约 142 MB 的运行时（走系统代理时可能很慢）。
  内存或网络受限时，优先使用 `desktop:pack:shell` 验证壳层，再在构建机上出完整包。

## 7. 关键配置约定

- `frontend-app/vite.config.ts`
  - `mode=production` 默认：`base=/m/`，`outDir=dist`
  - `mode=native` 默认：`base=/`，`outDir=dist-native`
- `frontend-app/capacitor.config.ts`
  - `webDir=dist-native`
- `frontend-app/.env.example`
  - 提供 `FRONTEND_APP_PUBLIC_BASE`、`VITE_BUILD_OUT_DIR`、`VITE_BACKEND_ENTRY_URL` 等覆写入口

## 8. 发布前检查清单

- `npm run build:frontend` 成功（网页端）。
- `npm run build:frontend:app:web` 成功（手机端 `/m/`）。
- `npm run build:frontend:app:native` 成功（手机端 Native）。
- `npm run mobile:cap:doctor` 通过（若要出手机端原生包）。
- 本地业务回归：模块 1/2/3/4 的上传、预览、处理入口不受影响。

## 9. 回滚策略

- 本次变更均在打包层，可通过 `git restore` 针对以下文件回滚：
  - `frontend-app/package.json`
  - `frontend-app/vite.config.ts`
  - `frontend-app/scripts/build-safe.mjs`
  - `frontend-app/capacitor.config.ts`
  - `frontend-app/.env.example`
  - `package.json`

## 10. 发布前最后收口（推荐执行顺序）

```powershell
# 完整体检（含 desktop doctor + web/native build + cap doctor + cap sync）
npm run release:preflight

# 快速体检（跳过 cap sync）
npm run release:preflight:quick

# 桌面端最终出包
npm run release:desktop

# 手机端同步到原生工程（供 Android/iOS IDE 出包）
npm run release:mobile:sync

# 桌面 + 手机一键全量收口
npm run release:all
```

说明：

- `release:preflight` 为发布前守门命令，建议每次发布前至少执行一次。
- `release:mobile:sync` 完成后，再进入 Android Studio / Xcode 做最终签名与打包。
