# 模型配置与代码命名规范化

日期：2026-10-29

范围已由维护者确认：联动清理命名、测试和本地配置，移除已禁用的旧模型分支及无效配置，保持当前模型、API 路由和有效数据路径。

## 现状与边界

首轮遍历 Git 跟踪文件 1,265 个，其中代码和配置文件 1,058 个，Python 文件 773 个。Python 语法及既有脚本文件命名规则检查通过，但约 120 个文件命中旧模型、旧服务地址或旧产品标识。

实际选用模型为 qwen-plus、qwen-max、qwen3-vl-plus、text-embedding-3-small。本轮不更换模型、不重构数据库、不重命名外部 API 路由，不修改用户上传和任务产物。已有且仍使用的 assistant_1 包及历史数据路径不做机械重命名。

OpenAI 兼容协议名称属于接口标准，不作为旧模型残留删除。第三方依赖自身的标识、合法框架覆写方法和锁文件中的完整性哈希不做文字替换。历史设计文档保留历史语境。

## 迁移设计

1. 将 GeminiEmbeddingClient、embedder_gemini.py 改为 EmbeddingClient、embedding_client.py；将 GeminiVisionExtractor 改为 VisionExtractor。同步内部回调、类型别名、任务统计字段、前后端读取和对应测试中的名称。
2. 模块二视觉配置统一使用 MODULE2_VISION_*，通用文本配置使用 MODULE2_LLM_*。清除 Gemini/Google 原生密钥、原生 URL、原生回退配置和已被禁用的传输实现。只保留 OpenAI 兼容视觉调用，保留其鉴权、重试、缓存和错误处理。
3. 向量默认模型统一为 text-embedding-3-small；清除 Embedding-V1、过期默认模型及旧服务地址。模块一不再暴露 zhipu_api_key 旧属性，内部使用 llm_api_key。
4. 检查所有本地 .env、示例和代码环境变量消费者，消除重复别名与无效开关。原有密钥值保留到有效新键，本地配置先备份到 Git 忽略目录，任何报告不记录密钥。
5. 检查运行脚本、打包配置和文档中的失效旧目录引用。已有有效启动与历史产物读取兼容不混入本轮删除。
6. 对全部代码和配置文件生成逐文件审计清单，记录检查范围、解析结果、迁移情况及保留理由，集中存放在 docs/operations/audits/。

## 错误与兼容处理

不支持的 provider 或 endpoint style 明确报错，不再接受被废弃的原生配置。测试使用当前模型或中立的测试模型名，不通过整体删除失败测试掩盖回归。原生传输专用测试随实现移除，新增兼容接口拒绝无效配置的覆盖。

本地配置迁移保持有效值；如果同一新键与旧键同时存在且值不同，优先保留现有新键，并在本地审计中只记录键名。API 请求/响应协议中不属于模型配置的兼容字段需逐项判断。
